# 求职项目介绍

项目名称：ICU 研究数据分析与模型评价平台（个人研究作品）。目标岗位：数据分析、医疗数据分析、BI 分析。

## 一分钟讲述

“我在开源医疗分析平台基础上，把虚构医院运营看板改造成 ICU 研究数据分析作品。我的重点是建立可信的数据口径：分别管理患者、住院和 ICU 停留，避免诊断与药品连接导致数量膨胀；通过分块 ETL、SQL 约束和自动检查建立分析库，再用交互看板展示患者结构、诊断处方、缺失与模型评价。真实数据仅在本地，公开演示用独立生成的模拟数据。模型部分区分判别与校准，并保留校准没有改善的结果。这是研究与数据分析作品，未在医院生产系统上线。”

## 简历写法（理解并能现场解释后使用）

- 在开源医疗分析框架基础上构建 ICU 数据分析作品，完成 Python 分块 ETL、患者/住院/ICU 分层数据模型及 SQL 指标体系，降低多表连接重复计数风险。
- 设计患者画像、诊断与处方、模型评价和数据质量六页看板，提供筛选、时点切换、汇总导出及 Power BI 接入材料。
- 建立唯一性、外键、患者分组、预测覆盖和概率误差复核，提供本地受限数据模式与独立模拟公开演示，明确统计口径和研究边界。

不要写“改善医院死亡率”“替医院节省成本”“上线服务多少医护人员”“完全独立从零原创”或“已部署 PostgreSQL/Power BI”——当前没有这些证据。项目周期和个人负责范围按实际填写，不编造实习或团队经历。

## 面试常见追问

1. 为什么患者数不等于 ICU 次数？同一个人可能多次住院，一次住院可能多次 ICU；必须依据问题选择主键和去重单位。
2. 怎样避免诊断与药品连接膨胀？保持独立事实表，在需要的粒度先聚合，再做一对一连接；见 SQL Q3 和重复就诊测试。
3. 为什么不能用所有出院诊断做早期特征？这些诊断可能在预测时点以后才能确定；描述性看板与预测特征必须区分。
4. AUROC 高就可用吗？AUROC 评价排序，Brier/校准评价概率；还需要外部、前瞻性和临床效用验证。当前只做研究内部评价。
5. 人口筛选后模型指标为何没变？现有模型指标是冻结全队列结果，UI 显式说明；避免把全局指标当子组指标。若要子组评估需重新按个体预测计算、报告置信区间并控制选择性分析。
6. 缺失率是不是错误率？不是，可能反映临床测量策略与病情。必须同时说明时间、分母和处理策略。
7. 为什么没做按月医院运营趋势？MIMIC 日期按患者独立偏移，跨患者月份不代表真实同月。
8. 怎样分享作品？只分享白名单生成的模拟包。真实数据、衍生模型与记录遵守数据协议，不能因为“去掉姓名”就上传。

## 五分钟演示顺序

总览说明三种计数 → 用科室/性别筛选患者画像 → 解释诊断/处方的统计单位 → 切换 1h 与 24h 观察校准 → 展示缺失率与质量检查 → 打开 SQL Q3 和一个防重复计数测试。以分析判断和证据为主，不逐行背代码。
